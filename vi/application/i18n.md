### Đa ngôn ngữ

`@nestjs/i18n` dịch những gì một ứng dụng Nest gửi về (response, lỗi, thông báo validation, các trường GraphQL) sang ngôn ngữ của từng request.

Một cửa hàng online bán thức ăn và đồ dùng cho mèo phục vụ khách hàng ở Mỹ, Ba Lan và Đức, và API đơn hàng của nó cần trả lời mỗi khách bằng chính ngôn ngữ của họ. Trong bài hướng dẫn này, bạn sẽ dịch xác nhận đơn hàng (với dạng số nhiều tiếng Ba Lan chính xác), thông báo lỗi, thông báo validation (từ `class-validator` hoặc từ Zod) và các trường GraphQL. Bạn cũng sẽ định dạng giá và ngày tháng theo từng locale.

Package resolve locale một lần cho mỗi request và giữ nó trong một store `AsyncLocalStorage`. Service, exception, pipe và field resolver của GraphQL đều dịch được mà không cần truy cập request object, và mọi provider vẫn là singleton. Nó hoạt động giống nhau trên Express và Fastify, cũng như với microservice và WebSocket gateway.

#### Cài đặt <a id="installation"></a>

Bài hướng dẫn này mở rộng API đơn hàng của cửa hàng, phục vụ khách hàng bằng tiếng Anh, tiếng Ba Lan và tiếng Đức. Đơn hàng là các object thuần lưu trong bộ nhớ. Ví dụ tạo sẵn đơn hàng #1001: hai túi hạt cá hồi và ba gói cát vệ sinh vón cục, tổng cộng $97.95. Đơn được đặt vào ngày 14 tháng 9 năm 2026 và đã được giao đi.

Cài package:

```bash
$ npm i --save @nestjs/i18n
```

Phần đầu tiên suy ra một type từ file JSON, nên hãy bật `resolveJsonModule` trong `tsconfig.json`.

#### Thêm catalog và đăng ký module <a id="add-catalogs-and-register-the-module"></a>

Bản dịch nằm trong các file JSON, mỗi locale một thư mục. Mỗi file trở thành một namespace mang tên của file, nên message `notFound` trong `orders.json` có key là `orders.notFound`.

```text
src
├── i18n
│   ├── de
│   │   ├── orders.json
│   │   └── validation.json
│   ├── en
│   │   ├── orders.json
│   │   └── validation.json
│   ├── pl
│   │   ├── orders.json
│   │   └── validation.json
│   └── translations.ts
├── orders
└── app.module.ts
```

Đây là catalog tiếng Anh cho đơn hàng. Các từ trong dấu ngoặc nhọn là placeholder, được điền từ các tham số bạn truyền vào khi dịch. `items` là một message số nhiều, được giải thích trong phần [Dịch xác nhận đơn hàng](/application/i18n#translate-order-confirmations).

```json
@@filename(src/i18n/en/orders.json)
{
  "items": {
    "one": "{count} item",
    "other": "{count} items"
  },
  "confirmed": "Thank you! Order #{id} is confirmed: {items}.",
  "notFound": "Order #{id} was not found.",
  "invalidId": "The order number must be a whole number.",
  "unknownProduct": "Product {id} is not in our catalog.",
  "tooManyItems": {
    "one": "{path} must not exceed {count} item per product",
    "other": "{path} must not exceed {count} items per product"
  },
  "unsupportedCountry": "We only ship to the United States, Poland and Germany.",
  "status": {
    "pending": "Awaiting payment",
    "paid": "Paid",
    "shipped": "Shipped"
  }
}
```

Trình biên dịch TypeScript không copy file JSON sang `dist`. Hãy thêm chúng vào [asset](/cli/monorepo#assets) trong `nest-cli.json`:

```json
{
  "compilerOptions": {
    "assets": ["i18n/**/*.json"],
    "watchAssets": true
  }
}
```

Giờ hãy đăng ký `I18nModule` trong root module:

```typescript
@@filename(app.module)
import { Module } from '@nestjs/common';
import {
  AcceptLanguageLocaleResolver,
  HeaderLocaleResolver,
  I18nModule,
  JsonI18nLoader,
  QueryLocaleResolver,
} from '@nestjs/i18n';
import { join } from 'node:path';
import { OrdersModule } from './orders/orders.module.js';

@Module({
  imports: [
    I18nModule.forRoot({
      defaultLocale: 'en',
      supportedLocales: ['en', 'pl', 'de'],
      fallbacks: { 'de-AT': 'de' },
      loader: new JsonI18nLoader({
        path: join(import.meta.dirname, 'i18n'),
      }),
      resolvers: [
        new QueryLocaleResolver('lang'),
        new HeaderLocaleResolver('x-lang'),
        new AcceptLanguageLocaleResolver(),
      ],
    }),
    OrdersModule,
  ],
})
export class AppModule {}
```

Module là global, và nó mount một middleware trên mọi route để resolve locale trước khi guard, interceptor, pipe và handler chạy. Việc resolve diễn ra như sau:

- **Các resolver chạy theo thứ tự.** Mỗi resolver trả về một hoặc nhiều ứng viên, và ứng viên đầu tiên khớp với một locale được hỗ trợ sẽ thắng. Ở đây, `?lang=pl` thắng header `x-lang`, và header này lại thắng `Accept-Language`.
- **`Accept-Language` được parse đúng chuẩn.** Các ngôn ngữ được sắp xếp theo giá trị `q`, và những ngôn ngữ không được hỗ trợ bị bỏ qua, nên `fr-CH, fr;q=0.9, de;q=0.8` được resolve thành `de`.
- **Vùng (region) khớp với ngôn ngữ gốc của nó.** `pl-PL` được resolve thành `pl`. Không cần cấu hình gì.
- **`fallbacks` giữ một vùng như một locale riêng.** `de-AT` được resolve thành `de-AT`, và message của nó lấy từ `de`. Locale có ý nghĩa khi [định dạng giá và ngày tháng](/application/i18n#format-prices-and-dates): khách hàng Áo sẽ thấy số được định dạng theo kiểu Áo. Một vùng không được liệt kê, như `de-CH`, được resolve thành `de` thuần.
- **Không có gì khớp, hoặc hoàn toàn không có request** (một cron job, một queue consumer): `defaultLocale` sẽ được dùng.

`CookieLocaleResolver` đọc một cookie thay vào đó, mặc định là `lang`, phù hợp cho site muốn nhớ ngôn ngữ mà khách truy cập đã chọn. Phần [Dùng ngôn ngữ đã lưu của khách hàng](/application/i18n#use-the-customers-saved-language) sẽ thêm một resolver của riêng bạn.

Mọi response đều cho biết nó được viết bằng locale nào. Middleware đặt `Content-Language` thành locale đã resolve và thêm các header mà resolver đọc vào `Vary`, ở đây là `Vary: x-lang, Accept-Language`, để cache giữ một bản cho mỗi ngôn ngữ. Đặt `responseHeaders: false` để tắt hành vi này.

`supportedLocales` là tùy chọn và mặc định là các thư mục mà loader tìm thấy. Cố định nó giúp một thư mục lạc chỗ không bao giờ trở thành locale.

Cuối cùng, hãy gán type cho các key. Catalog tiếng Anh là nguồn sự thật, và một câu import chỉ lấy type sẽ đọc cấu trúc của nó lúc compile mà không load file. Khối `declare module` đăng ký cấu trúc đó với package:

```typescript
@@filename(i18n/translations)
import type orders from './en/orders.json';
import type validation from './en/validation.json';

export interface Translations {
  orders: typeof orders;
  validation: typeof validation;
}

declare module '@nestjs/i18n' {
  interface I18nTypes {
    translations: Translations;
  }
}
```

Từ giờ trở đi, `I18nService` cùng các hàm helper mà bạn sẽ dùng để bản địa hóa exception và thông báo validation, `t()`, `i18nValidationMessage()` và `i18nIssueMessage()`, chỉ chấp nhận những key có trong catalog tiếng Anh. Một lỗi gõ như `orders.notFund` sẽ không compile được, và `orders.status` cũng vậy, vì nó là một namespace chứ không phải message. Một provider dịch từ catalog có cấu trúc khác, như catalog của một library, sẽ inject `I18nService<OtherTranslations>`, khi đó key được kiểm tra theo `OtherTranslations`.

#### Dịch xác nhận đơn hàng <a id="translate-order-confirmations"></a>

Khi khách hàng đặt hàng, API xác nhận đơn bằng một message có kèm số lượng sản phẩm. Inject `I18nService` vào `OrdersService` và gọi `t()`:

```typescript
@@filename(orders/orders.service)
@Injectable()
export class OrdersService {
  // ...
  constructor(private readonly i18nService: I18nService) {}

  create(userId: number, dto: CreateOrderDto) {
    const order: Order = {
      id: this.nextId++,
      userId,
      items: dto.items,
      total: this.priceOf(dto.items),
      status: 'pending',
      createdAt: new Date(),
    };
    this.orders.push(order);

    return {
      id: order.id,
      message: this.i18nService.t('orders.confirmed', {
        args: { id: order.id, items: this.describeItems(order) },
      }),
    };
  }

  describeItems(order: Order): string {
    const count = order.items.reduce((sum, item) => sum + item.quantity, 0);
    return this.i18nService.t('orders.items', { args: { count } });
  }
  // ...
}
```

Bạn không truyền locale vào `t()`. Nó đọc locale đã được resolve cho request hiện tại, dù `OrdersService` là một singleton không bao giờ nhìn thấy request. Chỉ đặt tùy chọn `locale` khi muốn ghi đè, ví dụ khi một background job gửi email cho khách hàng bằng ngôn ngữ lưu trong hồ sơ của họ. Tùy chọn này được so khớp giống như locale của request: `pl-PL` trở thành `pl`, và một locale bạn không hỗ trợ sẽ trở thành locale mặc định, nên một giá trị cũ trong hồ sơ không thể làm hỏng job.

Controller không có gì phụ thuộc locale cả:

```typescript
@@filename(orders/orders.controller)
@Controller('orders')
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}

  @Post()
  create(@Body() dto: CreateOrderDto) {
    // The Authentication tutorial replaces the fixed customer with the signed-in user.
    return this.ordersService.create(1, dto);
  }
}
```

Tiếng Anh và tiếng Đức có hai dạng số nhiều. Tiếng Ba Lan có bốn dạng, và một con số dùng dạng nào phụ thuộc vào các chữ số cuối của nó. Một message số nhiều là một object có key là các loại số nhiều (plural category):

```json
@@filename(src/i18n/pl/orders.json)
{
  "items": {
    "one": "{count} produkt",
    "few": "{count} produkty",
    "many": "{count} produktów",
    "other": "{count} produktu"
  },
  "confirmed": "Dziękujemy! Zamówienie #{id} zostało przyjęte: {items}.",
  "notFound": "Nie znaleziono zamówienia #{id}.",
  "invalidId": "Numer zamówienia musi być liczbą całkowitą.",
  "unknownProduct": "Produktu {id} nie ma w naszym katalogu.",
  "tooManyItems": {
    "one": "{path}: można zamówić najwyżej {count} sztukę jednego produktu",
    "few": "{path}: można zamówić najwyżej {count} sztuki jednego produktu",
    "many": "{path}: można zamówić najwyżej {count} sztuk jednego produktu",
    "other": "{path}: można zamówić najwyżej {count} sztuki jednego produktu"
  },
  "unsupportedCountry": "Wysyłamy tylko do Stanów Zjednoczonych, Polski i Niemiec.",
  "status": {
    "pending": "Oczekuje na płatność",
    "paid": "Opłacone",
    "shipped": "Wysłane"
  }
}
```

Khi các tham số có chứa một `count` dạng số, service sẽ chọn dạng phù hợp bằng `Intl.PluralRules` theo locale của message. Nếu thiếu một loại, `other` sẽ được dùng. File tiếng Đức giống file tiếng Anh, chỉ có dạng `one` và `other`.

| Số sản phẩm | Tiếng Anh | Tiếng Ba Lan | Tiếng Đức |
| --- | --- | --- | --- |
| 1 | 1 item | 1 produkt | 1 Produkt |
| 2 | 2 items | 2 produkty | 2 Produkte |
| 5 | 5 items | 5 produktów | 5 Produkte |
| 22 | 22 items | 22 produkty | 22 Produkte |

Lời xác nhận được ghép từ hai message: cụm từ số nhiều được dịch trước rồi chèn vào câu. Placeholder không lồng nhau được, nên đây là cách kết hợp chúng.

Tên của placeholder gồm chữ cái, chữ số và dấu gạch dưới. Một placeholder mà bạn không truyền tham số nào sẽ được giữ nguyên trong text, và mọi đoạn text khác trong dấu ngoặc nhọn cũng vậy. Để viết một dấu ngoặc nhọn cạnh tên, hãy viết nó hai lần: <code>{{ '{' }}{{ '{' }}id{{ '}' }}{{ '}' }}</code> sẽ in ra <code>{{ '{' }}id{{ '}' }}</code>. Với select, số thứ tự và so khớp chính xác, hãy [dùng cú pháp ICU message](/application/i18n#use-icu-message-syntax).

> info **Gợi ý** Chỉ tham số `count` mới chọn dạng số nhiều, nên hãy đặt tên nó là `count` trong mọi message số nhiều bạn dịch bằng `t()`. Nhờ type catalog đã đăng ký, `t()` sẽ không compile được nếu thiếu nó với message số nhiều. Thông báo validation tự động có `count`, như phần [Bản địa hóa thông báo validation](/application/i18n#localize-validation-messages) cho thấy.

#### Bản địa hóa exception <a id="localize-exceptions"></a>

Một đơn hàng không tồn tại nên trả về lỗi 404 bằng ngôn ngữ của khách hàng. Hãy dịch message ngay khi throw:

```typescript
@@filename(orders/orders.service)
findOne(id: number): Order {
  const order = this.orders.find((order) => order.id === id);
  if (!order) {
    throw new NotFoundException(this.i18nService.t('orders.notFound', { args: { id } }));
  }
  return order;
}
```

Exception mang theo text đã hoàn chỉnh, nên không cần cấu hình gì: exception filter mặc định của Nest, filter của riêng bạn, và phần định dạng lỗi của GraphQL đều nhận được message đã dịch. `GET /orders/999` với `x-lang: pl` trả về:

```json
{
  "message": "Nie znaleziono zamówienia #999.",
  "error": "Not Found",
  "statusCode": 404
}
```

Code không có sẵn `I18nService` có thể dùng hàm `t()`. Nó dịch cho request hiện tại theo cùng cách. Các pipe có sẵn như `ParseIntPipe` tạo ra message tiếng Anh, nên hãy cung cấp một exception factory cho pipe parse ID đơn hàng:

```typescript
@@filename(orders/orders.controller)
const orderIdPipe = new ParseIntPipe({
  exceptionFactory: () => new BadRequestException(t('orders.invalidId')),
});

@Controller('orders')
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}
  // ...

  @Get(':id')
  findOne(@Param('id', orderIdPipe) id: number) {
    return this.ordersService.getSummary(id);
  }
}
```

Pipe được tạo một lần, bên ngoài dependency injection, nhưng vẫn trả lời mỗi request bằng ngôn ngữ của nó. Bạn sẽ viết `getSummary()` trong phần [Định dạng giá và ngày tháng](/application/i18n#format-prices-and-dates).

Nếu API của bạn định hình lỗi bằng [exception filter](/exception-filters#binding-filters) riêng, ví dụ theo dạng problem details của RFC 9457, filter sẽ đọc message đã dịch như mọi message khác:

```typescript
@@filename(common/problem-details.filter)
import {
  Catch,
  NotFoundException,
  type ArgumentsHost,
  type ExceptionFilter,
} from '@nestjs/common';
import { HttpAdapterHost } from '@nestjs/core';

@Catch(NotFoundException)
export class ProblemDetailsFilter implements ExceptionFilter {
  constructor(private readonly httpAdapterHost: HttpAdapterHost) {}

  catch(exception: NotFoundException, host: ArgumentsHost) {
    const { httpAdapter } = this.httpAdapterHost;
    const response = host.switchToHttp().getResponse();
    httpAdapter.setHeader(response, 'Content-Type', 'application/problem+json');
    httpAdapter.reply(
      response,
      { type: 'about:blank', title: 'Not Found', status: 404, detail: exception.message },
      404,
    );
  }
}
```

Khi đã đăng ký filter, cùng request đó trả về:

```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "Nie znaleziono zamówienia #999."
}
```

#### Bản địa hóa thông báo validation <a id="localize-validation-messages"></a>

Bước này giả định ứng dụng của bạn validate request body bằng `class-validator`; nếu bạn validate bằng Zod hoặc một library Standard Schema khác, hãy đọc tiếp phần [Với Zod](#with-zod). `I18nValidationPipe` có thể thay thế trực tiếp cho [`ValidationPipe`](/application/validation#using-the-built-in-validationpipe) của Nest: nó nhận cùng các tùy chọn và chỉ dịch các message. Hãy bind nó ở chỗ `ValidationPipe` từng ở, ở đây là một provider `APP_PIPE` của `AppModule`:

```typescript
@@filename(app.module)
providers: [
  {
    provide: APP_PIPE,
    useValue: new I18nValidationPipe({ whitelist: true, transform: true }),
  },
],
```

Bắt đầu với DTO cho đơn hàng mới. Nó dùng các decorator của `class-validator` mà không có message nào:

```typescript
@@filename(orders/dto/create-order.dto)
import { i18nValidationMessage } from '@nestjs/i18n';
import { Type } from 'class-transformer';
import { ArrayNotEmpty, IsInt, IsString, Max, Min, ValidateNested } from 'class-validator';

export class OrderItemDto {
  @IsString()
  productId: string;

  @IsInt()
  @Min(1)
  @Max(10, { message: i18nValidationMessage('orders.tooManyItems') })
  quantity: number;
}

export class CreateOrderDto {
  @ArrayNotEmpty()
  @ValidateNested({ each: true })
  @Type(() => OrderItemDto)
  items: OrderItemDto[];
}
```

Một ràng buộc không có `message` sẽ được tra trong namespace `validation` theo tên ràng buộc: `@IsInt()` đọc `validation.isInt`, còn `@Min()` đọc `validation.min`. `i18nValidationMessage()` trỏ một ràng buộc cụ thể tới key bạn chọn, ở đây là một message riêng của cửa hàng cho giới hạn số lượng. Các message bạn viết dưới dạng chuỗi thuần được giữ nguyên. Một message có thể dùng các placeholder sau:

- `property`: tên trường, như `quantity`.
- `path`: đường dẫn có dấu chấm tính từ DTO, như `items.1.quantity`. Với trường ở cấp cao nhất, nó giống với `property`.
- `value`: giá trị bị từ chối, khi nó là chuỗi, số hoặc boolean.
- `constraint1`, `constraint2`, v.v.: các tham số của decorator. Một danh sách, như các giá trị mà `@IsIn()` chấp nhận, sẽ được viết thành `US, PL, DE`.
- `count`: tham số số đầu tiên, để message số nhiều khớp với nó. `@Max(10)` sẽ chọn dạng cho số 10.

Giới hạn số lượng là một message số nhiều (xem catalog tiếng Ba Lan trong phần [Dịch xác nhận đơn hàng](/application/i18n#translate-order-confirmations)), nên `@Max(10)` sẽ ra "10 sztuk" trong tiếng Ba Lan. Đây là catalog `validation` tiếng Ba Lan cho các ràng buộc mà bài hướng dẫn này dùng. `minLength` cũng là message số nhiều, nên `@MinLength(2)` ra "2 znaki" và `@MinLength(5)` ra "5 znaków":

```json
@@filename(src/i18n/pl/validation.json)
{
  "isInt": "{path} musi być liczbą całkowitą",
  "isString": "{path} musi być tekstem",
  "min": "{path} musi wynosić co najmniej {constraint1}",
  "arrayNotEmpty": "{path} musi zawierać co najmniej jeden element",
  "minLength": {
    "one": "{path} musi mieć co najmniej {count} znak",
    "few": "{path} musi mieć co najmniej {count} znaki",
    "many": "{path} musi mieć co najmniej {count} znaków",
    "other": "{path} musi mieć co najmniej {count} znaku"
  },
  "matches": "{path} ma nieprawidłowy format"
}
```

Một ràng buộc chưa có bản dịch sẽ giữ message của `class-validator`, nên bạn có thể dịch dần từng ràng buộc mình dùng.

Với object lồng nhau, `ValidationPipe` của Nest thêm đường dẫn của cha vào trước mỗi message. `I18nValidationPipe` giữ nguyên các message đã dịch, nên mỗi message tự quyết định: `path` cho ra `items.1.quantity`, còn `property` chỉ cho ra `quantity`. Các message chưa có bản dịch vẫn giữ prefix.

Khách hàng đặt địa chỉ giao hàng cho một đơn. DTO của nó dựa vào các mục `minLength` và `matches` của catalog, và chỉ định một message riêng của cửa hàng cho quốc gia:

```typescript
@@filename(orders/dto/shipping-address.dto)
import { i18nValidationMessage } from '@nestjs/i18n';
import { IsIn, Matches, MinLength } from 'class-validator';

export class ShippingAddressDto {
  @MinLength(2)
  recipient: string;

  @MinLength(2)
  city: string;

  @Matches(/^[0-9-]{5,6}$/)
  postalCode: string;

  @IsIn(['US', 'PL', 'DE'], { message: i18nValidationMessage('orders.unsupportedCountry') })
  country: 'US' | 'PL' | 'DE';
}
```

```typescript
@@filename(orders/orders.controller)
@Put(':id/shipping-address')
updateShippingAddress(
  @Param('id', orderIdPipe) id: number,
  @Body() address: ShippingAddressDto,
) {
  return this.ordersService.updateShippingAddress(id, address);
}
```

Một khách hàng Đức gửi tên người nhận chỉ có một chữ cái, mã bưu chính bốn chữ số và quốc gia là `AT` sẽ nhận về ba message đã dịch. Phần [Thử ngay](#try-it) cho thấy response.

##### Với Zod <a id="with-zod"></a>

Nếu ứng dụng của bạn validate bằng Zod, Valibot, ArkType hoặc một library [Standard Schema](https://standardschema.dev/) khác, hãy bind `I18nStandardSchemaValidationPipe` thay vì `I18nValidationPipe`. Đây là bản thay thế trực tiếp cho [`StandardSchemaValidationPipe`](/application/validation#schema-based-validation) của Nest, và một ứng dụng chỉ bind một trong hai pipe, không bind cả hai:

```typescript
@@filename(app.module)
providers: [{ provide: APP_PIPE, useValue: new I18nStandardSchemaValidationPipe() }],
```

Đây là cùng các đầu vào đó dưới dạng schema Zod. Message của library là chuỗi thuần, nên `i18nIssueMessage()` mã hóa một key bản dịch ngay trong message, cách này hoạt động với mọi library Standard Schema:

```typescript
@@filename(orders/orders.schemas)
import { i18nIssueMessage } from '@nestjs/i18n';
import { z } from 'zod';

export const orderItemSchema = z.object({
  productId: z.string(),
  quantity: z.number().int().min(1).max(10, i18nIssueMessage('orders.tooManyItems')),
});

export const createOrderSchema = z.object({
  items: z.array(orderItemSchema).nonempty(),
});
export type CreateOrderDto = z.infer<typeof createOrderSchema>;

export const shippingAddressSchema = z.object({
  recipient: z.string().min(2),
  city: z.string().min(2),
  postalCode: z.string().regex(/^[0-9-]{5,6}$/),
  country: z.enum(['US', 'PL', 'DE'], i18nIssueMessage('orders.unsupportedCountry')),
});
export type ShippingAddress = z.infer<typeof shippingAddressSchema>;
```

Các tham số body khai báo schema thay vì class:

```typescript
@@filename(orders/orders.controller)
import {
  createOrderSchema,
  shippingAddressSchema,
  type CreateOrderDto,
  type ShippingAddress,
} from './orders.schemas.js';
// ...
@Post()
create(@Body({ schema: createOrderSchema }) dto: CreateOrderDto) {
  // ...
}

@Put(':id/shipping-address')
updateShippingAddress(
  @Param('id', orderIdPipe) id: number,
  @Body({ schema: shippingAddressSchema }) address: ShippingAddress,
) {
  return this.ordersService.updateShippingAddress(id, address);
}
```

Một issue không có key tường minh sẽ được tra theo mã mà library gán cho nó, từ key cụ thể nhất đến ít cụ thể nhất:

- **Định dạng trước.** Một regex không khớp sẽ đọc `validation.invalid_format.regex`.
- **Sau đó là nguồn gốc.** Zod báo `too_small` cho cả chuỗi ngắn, số nhỏ lẫn mảng ngắn, và cho biết là loại nào trong `origin`. Một chuỗi ngắn sẽ đọc `validation.too_small.string`, để catalog có thể nói về số ký tự mà không nhầm con số.
- **Cuối cùng là chỉ mã**, như `validation.too_small`.

`type` của issue trong Valibot hoạt động theo cùng cách. Message có thể dùng các placeholder `property` và `path` như ở trên, text gốc của library dưới dạng `message`, và các tham số của issue, như `minimum` hoặc `expected`. `count` chứa `minimum` hoặc `maximum` dạng số, nên "2 znaki" và "5 znaków" đều ra đúng, và `orders.tooManyItems` cho `.max(10)` cũng vậy. Đây lại là catalog tiếng Ba Lan, với các mục theo mã issue đặt trước các tên ràng buộc:

```json
@@filename(src/i18n/pl/validation.json)
{
  "invalid_type": "{path} musi być typu {expected}",
  "too_small": {
    "string": {
      "one": "{path} musi mieć co najmniej {count} znak",
      "few": "{path} musi mieć co najmniej {count} znaki",
      "many": "{path} musi mieć co najmniej {count} znaków",
      "other": "{path} musi mieć co najmniej {count} znaku"
    },
    "number": "{path} musi wynosić co najmniej {minimum}",
    "array": "{path} musi zawierać co najmniej jeden element"
  },
  "invalid_format": {
    "regex": "{path} ma nieprawidłowy format"
  },
  "isInt": "{path} musi być liczbą całkowitą",
  "isString": "{path} musi być tekstem",
  "min": "{path} musi wynosić co najmniej {constraint1}",
  "arrayNotEmpty": "{path} musi zawierać co najmniej jeden element",
  "minLength": {
    "one": "{path} musi mieć co najmniej {count} znak",
    "few": "{path} musi mieć co najmniej {count} znaki",
    "many": "{path} musi mieć co najmniej {count} znaków",
    "other": "{path} musi mieć co najmniej {count} znaku"
  },
  "matches": "{path} ma nieprawidłowy format"
}
```

Với các mục này, địa chỉ giao hàng không hợp lệ trong phần [Thử ngay](#try-it) nhận được cùng ba message tiếng Đức như khi dùng class, còn đơn hàng không hợp lệ sẽ ra:

```json
{
  "message": [
    "items.0.quantity musi wynosić co najmniej 1",
    "items.1.productId musi być typu string",
    "items.1.quantity: można zamówić najwyżej 10 sztuk jednego produktu"
  ],
  "error": "Bad Request",
  "statusCode": 400

```

Các issue chưa có bản dịch giữ định dạng quen thuộc của Nest, đường dẫn rồi đến message của library.

#### Bản địa hóa các trường GraphQL <a id="localize-graphql-fields"></a>

Bước này áp dụng cho ứng dụng phục vụ GraphQL bằng `@nestjs/graphql`. Ứng dụng mobile đọc đơn hàng qua GraphQL, thông qua Apollo driver và một schema [code first](/graphql/quick-start#code-first) đăng ký trong `AppModule`:

```typescript
@@filename(app.module)
GraphQLModule.forRoot<ApolloDriverConfig>({
  driver: ApolloDriver,
  autoSchemaFile: true,
}),
```

Object type cung cấp dữ liệu đơn hàng thô:

```typescript
@@filename(orders/order.model)
import { Field, Float, Int, ObjectType } from '@nestjs/graphql';

@ObjectType('Order')
export class OrderModel {
  @Field(() => Int)
  id: number;

  @Field()
  status: string;

  @Field(() => Float)
  total: number;
}
```

Các trường bản địa hóa được tính bởi field resolver, với cùng `I18nService` mà REST controller dùng:

```typescript
@@filename(orders/orders.resolver)
import { Args, Int, Parent, Query, ResolveField, Resolver } from '@nestjs/graphql';
import { I18nService } from '@nestjs/i18n';
import type { Order } from './order.entity.js';
import { OrderModel } from './order.model.js';
import { OrdersService } from './orders.service.js';

@Resolver(() => OrderModel)
export class OrdersResolver {
  constructor(
    private readonly ordersService: OrdersService,
    private readonly i18nService: I18nService,
  ) {}

  @Query(() => OrderModel)
  order(@Args('id', { type: () => Int }) id: number) {
    return this.ordersService.findOne(id);
  }

  @ResolveField(() => String)
  statusLabel(@Parent() order: Order) {
    return this.i18nService.t(`orders.status.${order.status}`);
  }

  @ResolveField(() => String)
  items(@Parent() order: Order) {
    return this.ordersService.describeItems(order);
  }
}
```

Key `statusLabel` là một template literal tạo từ union `OrderStatus`, nên trình biên dịch vẫn kiểm tra được mọi trạng thái đều có nhãn.

Trên Express, Apollo được mount sau middleware của Nest, nên middleware locale trong phần [Thêm catalog và đăng ký module](/application/i18n#add-catalogs-and-register-the-module) bọc lấy mọi operation GraphQL. `?lang`, `x-lang` và `Accept-Language` hoạt động y như với REST, trong resolver, field resolver và guard. `NotFoundException` do `findOne()` throw ra đến được client ở dạng đã dịch, trong `errors[0].message`.

> warning **Cảnh báo** Middleware locale không bọc các subscription, vốn chạy qua WebSocket, hay một GraphQL driver được mount bên ngoài nó. Điều đó bao gồm cả trường hợp phổ biến là có [global prefix](/faq/global-prefix): Nest mount middleware dưới prefix, trong khi Apollo vẫn ở `/graphql`, nên hãy đặt `useGlobalPrefix: true` trên `GraphQLModule` khi dùng prefix. Ở những chỗ middleware không chạy, package quay về dùng một global interceptor, interceptor này đọc locale từ request trên GraphQL context (với subscription là WebSocket handshake) và chạy sau guard. Field resolver, kể cả của các event subscription, chỉ được bao phủ nếu bạn đặt `fieldResolverEnhancers: ['interceptors']`, guard sẽ không thấy locale, và response không mang `Content-Language`.

#### Định dạng giá và ngày tháng <a id="format-prices-and-dates"></a>

Phần tóm tắt đơn hàng hiển thị trạng thái, số lượng sản phẩm, tổng tiền và ngày đặt hàng, được định dạng theo cách mà mỗi khách hàng mong đợi:

```typescript
@@filename(orders/orders.service)
getSummary(id: number) {
  const order = this.findOne(id);
  return {
    id: order.id,
    status: this.i18nService.t(`orders.status.${order.status}`),
    items: this.describeItems(order),
    total: this.i18nService.formatNumber(order.total, { style: 'currency', currency: 'USD' }),
    placedAt: this.i18nService.formatDate(order.createdAt, {
      dateStyle: 'long',
      timeZone: 'UTC',
    }),
  };
}
```

`formatNumber()` và `formatDate()` bọc `Intl.NumberFormat` và `Intl.DateTimeFormat` với locale của request. Chúng nhận các tùy chọn `Intl` thông thường, cộng thêm tùy chọn `locale` để ghi đè locale hiện tại, giống như trong `t()`. Với đơn hàng #1001:

| Locale | `total` | `placedAt` |
| --- | --- | --- |
| `en` | $97.95 | September 14, 2026 |
| `pl` | 97,95 USD | 14 września 2026 |
| `de` | 97,95 $ | 14. September 2026 |
| `de-AT` | $ 97,95 | 14. September 2026 |

`de-AT` được định dạng theo kiểu Áo vì phần đăng ký module đã liệt kê nó trong `fallbacks`. Message của nó vẫn lấy từ catalog tiếng Đức.

Có hai thứ mà locale không quyết định:

- **Tiền tệ.** Locale điều khiển cách viết một số tiền, không phải giá trị của nó. Cửa hàng tính tiền bằng đô la Mỹ, nên mọi khách hàng đều thấy USD. Hãy lấy tiền tệ từ đơn hàng hoặc từ cửa hàng, đừng bao giờ lấy từ locale.
- **Múi giờ.** Không có `timeZone`, ngày tháng được định dạng theo múi giờ của server, điều này có thể làm lệch ngày. Hãy truyền múi giờ của khách hàng nếu bạn có lưu, hoặc định dạng theo UTC như ở đây.

#### Dùng ngôn ngữ đã lưu của khách hàng <a id="use-the-customers-saved-language"></a>

Khách hàng chọn ngôn ngữ khi đăng ký, và bản ghi khách hàng giữ nó trong trường `locale`, giống như bảng `customers` trong [chương mail](/application/mail#send-it-in-the-customers-language). Ở đây, `CustomersService` giữ khách hàng trong bộ nhớ, như `OrdersService` giữ đơn hàng. Với một khách hàng đã đăng nhập, lựa chọn đó nên thắng `Accept-Language`, vốn chỉ là giá trị mặc định của trình duyệt. Guard của [`@nestjs/authentication`](/security/authentication), giống như guard của Passport, đặt người dùng đã đăng nhập vào `request.user`.

Các resolver chạy trong middleware locale, trước guard, khi chưa có ai đăng nhập. Một resolver đặt `afterGuards` sẽ chạy sau guard, và nhận `executionContext` của lời gọi:

```typescript
@@filename(customers/customer-locale.resolver)
import { Injectable } from '@nestjs/common';
import { LocaleResolver, type LocaleResolverInput } from '@nestjs/i18n';
import { CustomersService } from './customers.service.js';

@Injectable()
export class CustomerLocaleResolver extends LocaleResolver {
  // After guards, the authentication guard has put the signed-in user on the request
  readonly afterGuards = true;

  constructor(private readonly customersService: CustomersService) {
    super();
  }

  resolve({ executionContext }: LocaleResolverInput) {
    const request = executionContext?.switchToHttp().getRequest<{ user?: { id: number } }>();
    const user = request?.user;
    return user ? this.customersService.findOne(user.id)?.locale : undefined;
  }
}
```

Nest khởi tạo class resolver, nên nó có thể inject provider. Hãy đặt nó vào `resolvers` ở thứ hạng mong muốn, và import module cung cấp những gì nó inject:

```typescript
@@filename(app.module)
I18nModule.forRoot({
  // ...
  resolvers: [
    new QueryLocaleResolver('lang'),
    new HeaderLocaleResolver('x-lang'),
    CustomerLocaleResolver,
    new AcceptLanguageLocaleResolver(),
  ],
  imports: [CustomersModule],
  // ...
}),
```

Thứ tự của các resolver vẫn quyết định:

- **`?lang` và `x-lang` thắng.** Chúng là lựa chọn dành riêng cho request này, từ một link chuyển ngôn ngữ hoặc một thiết lập trong app. Khi một trong hai khớp, resolver khách hàng sẽ không chạy.
- **Ngôn ngữ đã lưu thắng `Accept-Language`.** Zofia lưu tiếng Ba Lan, nên cô ấy đọc tiếng Ba Lan trên bất kỳ trình duyệt nào. Lukas lưu `de-AT`, giá trị này được so khớp như mọi ứng viên khác, nên anh ấy thấy định dạng kiểu Áo.
- **Khách hàng ẩn danh, và khách hàng không có ngôn ngữ đã lưu được hỗ trợ,** sẽ nhận những gì các resolver phía sau tìm được, ở đây là từ `Accept-Language`.

Guard thấy locale mà các resolver chạy trước guard tìm được, và response cho lỗi do guard throw, như 401, cũng vậy. Handler, và mọi thứ sau nó, thấy locale của khách hàng. Resolver chạy một lần cho mỗi request, kể cả với một operation GraphQL có nhiều trường gốc. Qua GraphQL, request nằm ở `GqlExecutionContext.create(executionContext).getContext().req`.

> info **Gợi ý** Giờ đây response cho một khách hàng đã đăng nhập phụ thuộc vào việc ai đang hỏi. Những response như vậy thường vốn đã là private, nhưng nếu có shared cache lưu chúng, hãy liệt kê header định danh khách hàng, như `Authorization`, trong `varyHeaders` của resolver, và middleware sẽ thêm nó vào `Vary`.

Khi khách hàng đổi ngôn ngữ, hãy trả lời họ bằng ngôn ngữ mới ngay lập tức. `I18nContext.setLocale()` thay đổi locale cho phần còn lại của request, bao gồm cả `Content-Language`:

```typescript
@@filename(customers/customers.controller)
@Controller('customers')
export class CustomersController {
  constructor(
    private readonly customersService: CustomersService,
    private readonly i18nContext: I18nContext,
    private readonly i18nService: I18nService,
  ) {}

  @Put('me/locale')
  updateLocale(@Req() request: { user: { id: number } }, @Body('locale') locale: string) {
    const supported = this.i18nContext.setLocale(locale);
    if (!supported) {
      throw new BadRequestException(this.i18nService.t('customers.unsupportedLocale'));
    }

    this.customersService.updateLocale(request.user.id, supported);
    return { locale: supported, message: this.i18nService.t('customers.localeUpdated') };
  }
}
```

`setLocale()` so khớp locale giống như quá trình resolve và trả về kết quả khớp: `de-DE` trở thành `de`. Với một ngôn ngữ mà cửa hàng không hỗ trợ, nó trả về `undefined` và giữ nguyên locale, nên lỗi được viết bằng ngôn ngữ khách hàng đang đọc. Hai message này nằm trong một catalog `customers` mới ở mỗi ngôn ngữ, được đăng ký bằng `customers: typeof customers` trong `Translations`:

```json
@@filename(src/i18n/de/customers.json)
{
  "localeUpdated": "Erledigt! Ab jetzt schreiben wir Ihnen auf Deutsch.",
  "unsupportedLocale": "Wir schreiben nur auf Englisch, Polnisch und Deutsch."
}
```

#### Microservice và WebSocket gateway <a id="microservices-and-websocket-gateways"></a>

Message handler và WebSocket gateway không đi qua HTTP middleware. Ở đó, module resolve locale trong một global interceptor, với cùng các resolver, nên service, exception và hàm `t()` hoạt động như với HTTP request.

Một message không có header hay query string, nhưng resolver nhận được `executionContext`, nên một resolver có thể đọc locale mà producer đặt ngay trong message. Hãy thêm nó vào `resolvers` của `I18nModule` trong microservice:

```typescript
@@filename(common/message-locale.resolver)
import { LocaleResolver, type LocaleResolverInput } from '@nestjs/i18n';

export class MessageLocaleResolver extends LocaleResolver {
  resolve({ executionContext }: LocaleResolverInput) {
    if (executionContext?.getType() !== 'rpc') {
      return undefined;
    }
    return executionContext.switchToRpc().getData<{ locale?: string }>()?.locale;
  }
}
```

Một resolver có thể đọc metadata transport của message theo cùng cách, như header của một message NATS hoặc Kafka, từ `executionContext.switchToRpc().getContext()`.

Với gateway, các resolver có sẵn đọc header và query string của upgrade request của kết nối. Socket.IO giữ request đó làm handshake, và resolver tìm thấy nó ở đó. Library `ws`, đứng sau `WsAdapter` của `@nestjs/platform-ws`, không giữ gì cả, nên hãy lưu request vào `client.request` khi client kết nối (`WsAuthenticator` của `@nestjs/authentication` cũng làm như vậy):

```typescript
@@filename(orders/order-updates.gateway)
@WebSocketGateway({ path: '/orders/updates' })
export class OrderUpdatesGateway implements OnGatewayConnection {
  constructor(private readonly ordersService: OrdersService) {}

  handleConnection(client: WebSocket & { request?: IncomingMessage }, request: IncomingMessage) {
    // The ws library keeps no reference to the upgrade request, whose headers and query the resolvers read
    client.request = request;
  }

  @SubscribeMessage('orders.summary')
  summary(@MessageBody() id: number) {
    return { event: 'orders.summary', data: this.ordersService.getSummary(id) };
  }
}
```

Một client kết nối tới `/orders/updates?lang=de` sẽ đọc tóm tắt bằng tiếng Đức. Interceptor chạy sau guard, nên trên các đường này guard thấy locale mặc định, và lỗi do guard throw sẽ ở locale mặc định. Pipe và handler thấy locale đã resolve, và resolver có `afterGuards` không cần gì thêm: ở đây mọi resolver đều đã chạy sau guard.
#### Xử lý key bị thiếu và reload catalog <a id="handle-missing-keys-and-reload-catalogs"></a>

Một bản dịch bị thiếu nên làm hỏng build ở môi trường development và CI, và lặng lẽ xuống cấp trên production. Đây là `AppModule` cuối cùng:

```typescript
@@filename(app.module)
import { ApolloDriver, type ApolloDriverConfig } from '@nestjs/apollo';
import { Module } from '@nestjs/common';
import { APP_PIPE } from '@nestjs/core';
import { GraphQLModule } from '@nestjs/graphql';
import {
  AcceptLanguageLocaleResolver,
  HeaderLocaleResolver,
  I18nModule,
  I18nValidationPipe,
  JsonI18nLoader,
  QueryLocaleResolver,
} from '@nestjs/i18n';
import { join } from 'node:path';
import { CustomerLocaleResolver } from './customers/customer-locale.resolver.js';
import { CustomersModule } from './customers/customers.module.js';
import { OrdersModule } from './orders/orders.module.js';

const env = process.env.NODE_ENV ?? 'development';

@Module({
  imports: [
    I18nModule.forRoot({
      defaultLocale: 'en',
      supportedLocales: ['en', 'pl', 'de'],
      fallbacks: { 'de-AT': 'de' },
      loader: new JsonI18nLoader({
        path: join(import.meta.dirname, 'i18n'),
        watch: env === 'development',
      }),
      resolvers: [
        new QueryLocaleResolver('lang'),
        new HeaderLocaleResolver('x-lang'),
        CustomerLocaleResolver,
        new AcceptLanguageLocaleResolver(),
      ],
      imports: [CustomersModule],
      missingKey: env === 'production' ? 'fallback' : 'throw',
    }),
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      autoSchemaFile: true,
    }),
    CustomersModule,
    OrdersModule,
  ],
  providers: [
    {
      provide: APP_PIPE,
      useValue: new I18nValidationPipe({ whitelist: true, transform: true }),
    },
  ],
})
export class AppModule {}
```

Tùy chọn `missingKey` quyết định điều gì xảy ra khi không tìm thấy key cho locale được yêu cầu:

- **`'throw'` ngoài production.** `t()` và `translate()` throw một `I18nMissingKeyError`, và request thất bại với lỗi 500. Một message tiếng Ba Lan chỉ có ở tiếng Anh cũng thất bại, vì policy này không bao giờ quay về locale mặc định. Vitest đặt `NODE_ENV` thành `test`, nên test suite của bạn chạy với policy này.
- **`'fallback'` trên production.** Một message tiếng Ba Lan bị thiếu sẽ được lấy từ locale mặc định là tiếng Anh, kèm một cảnh báo nêu tên key và locale, mỗi cặp một lần. Một key không tồn tại ở đâu cả sẽ trả về chính key đó và log một cảnh báo, mỗi key một lần.

Việc fallback từ `de-AT` sang `de` và việc so khớp vùng với ngôn ngữ gốc áp dụng với mọi policy. Thông báo validation tra theo tên ràng buộc hoặc mã issue cũng không bao giờ throw: một ràng buộc hoặc issue chưa có bản dịch sẽ giữ message của library. Các key bạn chỉ định bằng `i18nValidationMessage()` hoặc `i18nIssueMessage()` tuân theo policy, giống như `t()`. Các policy khác là `'key'`, `'empty'` và một hàm nhận key và locale.

> info **Gợi ý** Fallback hoạt động theo từng key. Khi message được ghép như trong phần [Dịch xác nhận đơn hàng](/application/i18n#translate-order-confirmations), một khách hàng Ba Lan có thể nhận một câu tiếng Anh bao quanh một cụm số nhiều tiếng Ba Lan. Cảnh báo sẽ cho bạn biết khi chuyện này xảy ra; bài test catalog trong phần [Test](/application/i18n#testing) giúp ngăn nó lọt lên production.

Với `watch: true`, JSON loader theo dõi thư mục catalog và reload khi có file thay đổi, để người dịch có thể sửa message mà không cần khởi động lại app. Chỉ bật tùy chọn này trong development:

- **Reload là nguyên tử.** Toàn bộ catalog được đọc lại và hoán đổi trong một bước, nên một request không bao giờ thấy lẫn lộn message cũ và mới.
- **File hỏng bị bỏ qua.** Nếu một file không parse được, catalog trước đó vẫn được dùng, và lỗi được log kèm đường dẫn file. Lần lưu hợp lệ tiếp theo sẽ được nhận.
- **Việc theo dõi dừng khi tắt ứng dụng.** Watcher đóng lại khi ứng dụng đóng. Hãy gọi `app.enableShutdownHooks()` trong `main.ts` để đóng nó cả khi nhận tín hiệu kết thúc.

Khi bật `watchAssets` trong `nest-cli.json`, CLI sẽ copy các catalog đã sửa sang `dist`, nơi loader đọc chúng.

##### Tùy chọn lấy từ cấu hình <a id="options-from-configuration"></a>

Bài hướng dẫn đọc trực tiếp `process.env` cho ngắn gọn. Trong một ứng dụng thực tế, hãy load môi trường qua [`@nestjs/config`](/application/configuration) với một validation schema, và đăng ký module bằng `forRootAsync()`. Factory của nó nhận `ConfigService` được inject và trả về các tùy chọn:

```typescript
@@filename(app.module)
I18nModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => {
    const env = configService.get<string>('NODE_ENV', 'development');
    return {
      defaultLocale: 'en',
      supportedLocales: ['en', 'pl', 'de'],
      fallbacks: { 'de-AT': 'de' },
      loader: new JsonI18nLoader({
        path: join(import.meta.dirname, 'i18n'),
        watch: env === 'development',
      }),
      missingKey: env === 'production' ? 'fallback' : 'throw',
    };
  },
  // The list has a class, which Nest instantiates, so it stays next to useFactory
  resolvers: [
    new QueryLocaleResolver('lang'),
    new HeaderLocaleResolver('x-lang'),
    CustomerLocaleResolver,
    new AcceptLanguageLocaleResolver(),
  ],
  imports: [CustomersModule],
}),
```

Factory có thể trả về instance của loader, resolver và formatter, nhưng không trả về class: Nest khởi tạo class trong lúc dựng module, trước khi bất kỳ factory nào chạy. Vì vậy `resolvers`, vốn liệt kê `CustomerLocaleResolver`, vẫn nằm ở cấp cao nhất cùng với `imports`. Một factory trả về class, hoặc một tùy chọn được đặt ở cả hai nơi, sẽ lỗi lúc khởi động với thông báo nêu tên tùy chọn.

Để giữ các tùy chọn trong một class riêng, hãy truyền nó làm `useClass`. Class này implement `I18nOptionsFactory`, và Nest gọi method `createI18nOptions()` của nó:

```typescript
@@filename(i18n/i18n-config.service)
@Injectable()
export class I18nConfigService implements I18nOptionsFactory {
  constructor(private readonly configService: ConfigService) {}

  createI18nOptions(): I18nModuleOptions {
    const env = this.configService.get<string>('NODE_ENV', 'development');
    return {
      defaultLocale: 'en',
      // ...
    };
  }
}
```

```typescript
@@filename(app.module)
I18nModule.forRootAsync({
  useClass: I18nConfigService,
  resolvers: [
    // ...
  ],
  imports: [CustomersModule],
}),
```

Các tùy chọn cuối cùng của module có thể inject bằng token `I18N_MODULE_OPTIONS`, dành cho provider của riêng bạn phụ thuộc vào chúng.

##### Loader tùy chỉnh <a id="a-custom-loader"></a>

Người dịch thường làm việc trên một nền tảng dịch thuật, nơi export mọi catalog thành một tài liệu JSON duy nhất. Một loader kế thừa `I18nLoader`: `load()` trả về các catalog theo key là locale, còn `watch()` (tùy chọn) truyền catalog mới cho một callback, để hot reload. Loader này tải bản export lúc khởi động, và tải lại mỗi năm phút:

```typescript
@@filename(i18n/remote-i18n.loader)
import { Logger } from '@nestjs/common';
import { I18nLoader, type I18nCatalogs } from '@nestjs/i18n';

/** Catalogs a translation platform exports as one JSON document, fetched again every `interval` ms. */
export class RemoteI18nLoader extends I18nLoader {
  private readonly logger = new Logger(RemoteI18nLoader.name);

  constructor(
    private readonly url: string,
    private readonly interval = 5 * 60_000,
  ) {
    super();
  }

  async load(): Promise<I18nCatalogs> {
    const response = await fetch(this.url, { signal: AbortSignal.timeout(10_000) });
    if (!response.ok) {
      throw new Error(`GET ${this.url} answered ${response.status}`);
    }
    return (await response.json()) as I18nCatalogs;
  }

  watch(onChange: (catalogs: I18nCatalogs) => void): () => void {
    const timer = setInterval(() => {
      this.load().then(onChange, (err: Error) =>
        this.logger.warn(`Keeping the current catalogs: ${err.message}`),
      );
    }, this.interval);
    // Polling alone doesn't keep the process alive
    timer.unref();
    return () => clearInterval(timer);
  }
}
```

Truyền một instance làm `loader`. Một lần tải lỗi lúc khởi động sẽ làm bootstrap thất bại, còn một lần poll lỗi sẽ giữ các catalog đang dùng. Module gọi `watch()` khi khởi tạo, và gọi hàm mà `watch()` trả về khi tắt. Catalog mới được kiểm tra giống như lần đầu, và một bộ catalog không phù hợp, như bộ không có catalog cho locale mặc định, sẽ được log và bỏ qua. Để đọc catalog từ database, hãy truyền một class loader thay vào đó, Nest sẽ khởi tạo nó với repository mà nó inject, và liệt kê module của repository trong `imports`.

#### Dùng cú pháp ICU message <a id="use-icu-message-syntax"></a>

Cú pháp có sẵn có placeholder và dạng số nhiều dưới dạng object trong catalog. Các nền tảng dịch thuật như Crowdin và Lokalise thường export catalog theo ICU MessageFormat, cú pháp này còn có so khớp chính xác như `=0`, `select` (cho message phụ thuộc vào một giá trị, như loài thú cưng), và `selectordinal` (thứ 1, thứ 2, thứ 3). Đây là message `items` tiếng Ba Lan viết bằng ICU:

```json
{
  "items": "{count, plural, one {# produkt} few {# produkty} many {# produktów} other {# produktu}}"
}
```

Tùy chọn `formatter` cho phép cắm vào một cú pháp khác. Một formatter kế thừa `I18nMessageFormatter` và implement `format()`, method nhận message, các tham số và locale. Formatter này chuyển message cho library [`intl-messageformat`](https://formatjs.github.io/docs/intl-messageformat/), library mà ứng dụng của bạn tự cài:

```typescript
@@filename(i18n/icu-message.formatter)
import { I18nMessageFormatter } from '@nestjs/i18n';
import { IntlMessageFormat } from 'intl-messageformat';

export class IcuMessageFormatter extends I18nMessageFormatter {
  // Parsing a message costs far more than formatting it, and the catalogs hold a fixed set
  private readonly compiled = new Map<string, IntlMessageFormat>();

  format(message: string, args: Record<string, unknown>, locale: string): string {
    const key = `${locale}\u0000${message}`;
    let compiled = this.compiled.get(key);
    if (!compiled) {
      compiled = new IntlMessageFormat(message, locale, undefined, { ignoreTag: true });
      this.compiled.set(key, compiled);
    }
    return String(compiled.format<unknown>(args));
  }
}
```

`ignoreTag` giữ `<` và `>` dưới dạng text, nếu không library sẽ đọc chúng thành thẻ rich-text. Truyền một instance, hoặc một class để Nest khởi tạo, làm `formatter`:

```typescript
@@filename(app.module)
I18nModule.forRoot({
  // ...
  formatter: new IcuMessageFormatter(),
}),
```

Khi đã có formatter:

- **Các catalog trong bài hướng dẫn vẫn dùng nguyên vẹn.** Một placeholder là một tham số ICU đơn giản, và object số nhiều vẫn hoạt động: module chọn dạng, còn formatter định dạng nó. `items` tiếng Ba Lan ra "5 produktów" cả khi là object số nhiều lẫn khi là message ICU ở trên.
- **Locale là của request.** Một message mà `de-AT` đọc từ catalog tiếng Đức được định dạng cho `de-AT`, nên một tham số số với kiểu tiền tệ sẽ ra `$ 97,95`. Một message đã fallback về locale mặc định được định dạng cho locale mặc định, vì nó được viết theo ngữ pháp của locale đó.
- **Key vẫn được kiểm tra, còn count số nhiều thì không.** Trình biên dịch yêu cầu một `count` dạng số cho object số nhiều, nhưng với nó một plural ICU chỉ là chuỗi, nên bạn phải tự truyền tham số.

#### Thử ngay <a id="try-it"></a>

#### Test <a id="testing"></a>

Một [end-to-end test](/fundamentals/testing#end-to-end-testing) đặt ngôn ngữ theo cùng cách mà client làm:

```typescript
@@filename(test/orders.e2e.spec)
import type { INestApplication } from '@nestjs/common';
import { Test } from '@nestjs/testing';
import request from 'supertest';
import { AppModule } from '../src/app.module.js';

describe('Orders (e2e)', () => {
  let app: INestApplication;

  beforeAll(async () => {
    const moduleRef = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();
    app = moduleRef.createNestApplication();
    await app.listen(0, '127.0.0.1');
  });

  afterAll(() => app.close());

  it('confirms an order in the language of the request', async () => {
    const res = await request(app.getHttpServer())
      .post('/orders')
      .set('Accept-Language', 'pl-PL,pl;q=0.9')
      .send({ items: [{ productId: 'salmon-kibble-2kg', quantity: 5 }] })
      .expect(201);

    expect(res.body.message).toBe(
      'Dziękujemy! Zamówienie #1002 zostało przyjęte: 5 produktów.',
    );
  });

  it('localizes errors', async () => {
    const res = await request(app.getHttpServer())
      .get('/orders/999?lang=de')
      .expect(404);

    expect(res.body.message).toBe('Bestellung #999 wurde nicht gefunden.');
  });

```

Bên ngoài request, `I18nService` dùng locale mặc định. Để test một service bằng ngôn ngữ khác mà không cần HTTP, hãy chạy lời gọi bên trong `I18nContext.run()`, hàm này đặt locale hiện tại giống như một request:

```typescript
@@filename(test/orders.service.spec)
import { I18nContext } from '@nestjs/i18n';
import { Test } from '@nestjs/testing';
import { AppModule } from '../src/app.module.js';
import { OrdersService } from '../src/orders/orders.service.js';

describe('OrdersService', () => {
  let ordersService: OrdersService;
  let i18nContext: I18nContext;

  beforeAll(async () => {
    const moduleRef = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();
    ordersService = moduleRef.get(OrdersService);
    i18nContext = moduleRef.get(I18nContext);
  });

  it.each([
    [1, '1 produkt'],
    [2, '2 produkty'],
    [5, '5 produktów'],
    [22, '22 produkty'],
  ])('describes %i item(s) in Polish', (quantity, expected) => {
    const order = {
      ...ordersService.findOne(1001),
      items: [{ productId: 'salmon-kibble-2kg', quantity }],
    };
    expect(i18nContext.run('pl', () => ordersService.describeItems(order))).toBe(expected);
  });

  it('falls back to the default locale outside a request', () => {
    const order = ordersService.findOne(1001);
    expect(ordersService.describeItems(order)).toBe('5 items');
  });
});
```

Để chạy ứng dụng với các catalog khác, ví dụ với một bản dịch bị xóa để test policy key bị thiếu, hãy thay loader trên testing module: `overrideProvider(I18nLoader).useValue(new InMemoryI18nLoader(catalogs))`.

Policy `'throw'` bắt được key bị thiếu trên những đường code mà test của bạn chạy qua. Một bài test catalog bắt phần còn lại: mọi locale phải có cùng key và placeholder như tiếng Anh, và mọi message số nhiều phải có đủ các dạng mà ngôn ngữ đó cần. `Intl.PluralRules` biết đó là những dạng nào:

```typescript
@@filename(test/catalogs.spec)
import { JsonI18nLoader, type I18nCatalog } from '@nestjs/i18n';
import { join } from 'node:path';

type Message = string | Record<string, string>;

/** Flattens a catalog to [key, message] pairs; plural forms count as one message. */
function messages(tree: I18nCatalog, prefix = ''): [string, Message][] {
  return Object.entries(tree).flatMap(([name, value]): [string, Message][] =>
    typeof value === 'string' || 'other' in value
      ? [[prefix + name, value as Message]]
      : messages(value, `${prefix}${name}.`),
  );
}

const placeholders = (message: Message) =>
  [...new Set(JSON.stringify(message).match(/\{\w+\}/g))].sort();

const loader = new JsonI18nLoader({ path: join(import.meta.dirname, '../src/i18n') });
const catalogs = await loader.load();
const english = new Map(messages(catalogs.en));

describe.each(Object.keys(catalogs))('the %s catalog', (lang) => {
  const translated = new Map(messages(catalogs[lang]));

  it('has the same keys and placeholders as the English one', () => {
    expect([...translated.keys()].sort()).toEqual([...english.keys()].sort());
    for (const [key, message] of translated) {
      expect(placeholders(message), key).toEqual(placeholders(english.get(key)!));
    }
  });

  it('has every plural form the language needs', () => {
    const forms = new Intl.PluralRules(lang).resolvedOptions().pluralCategories;
    for (const [key, message] of translated) {
      if (typeof message === 'object') {
        expect(Object.keys(message), key).toEqual(expect.arrayContaining(forms));
      }
    }
  });
});
```

Xóa dạng `many` khỏi message `items` tiếng Ba Lan, và bài test thứ hai sẽ thất bại kèm danh sách các dạng mà tiếng Ba Lan cần.

#### Checklist cho production <a id="production-checklist"></a>

- **Ship kèm các catalog.** Kiểm tra `dist/i18n` có tồn tại sau `nest build` không. Loader đọc thư mục này lúc khởi động, và thiếu thư mục sẽ làm bootstrap thất bại.
- **Dùng `'fallback'` trên production và `'throw'` ở mọi nơi khác**, và chạy bài test catalog trong CI. Theo dõi log production để phát hiện các cảnh báo fallback.
- **Tắt `watch` trên production.** Hot reload là công cụ cho development.
- **Cố định `supportedLocales`.** Nếu không, mọi thư mục dưới `i18n` đều trở thành locale, kể cả thư mục xuất hiện khi app đang chạy với `watch` được bật.
- **Thêm các vùng cần định dạng riêng vào `fallbacks`.** Một vùng sẽ được resolve thành ngôn ngữ gốc của nó trừ khi được liệt kê, và khi đó nó cũng được định dạng như ngôn ngữ gốc.
- **Đặt locale bên ngoài request.** Cron job, queue consumer và email gửi đi không có request, nên ở đó `I18nService` quay về locale mặc định, còn hàm `t()` trả về key. Hãy lưu locale ưa thích của mỗi khách hàng, và chạy công việc bên trong `I18nContext.run()`.
- **Chú ý cache.** Response cho cùng một URL khác nhau theo `Accept-Language` và `x-lang`. Middleware liệt kê cả hai trong `Vary`; hãy kiểm tra cache hoặc CDN của bạn có tôn trọng nó không. Query parameter `lang` là một phần của URL, nên không cần làm gì thêm.
- **Giữ GraphQL dưới global prefix.** Với `setGlobalPrefix()`, middleware locale chỉ bao phủ các route dưới prefix. Hãy đặt `useGlobalPrefix: true` cho `GraphQLModule`, nếu không guard trên resolver sẽ không còn thấy locale (xem [Bản địa hóa các trường GraphQL](/application/i18n#localize-graphql-fields)).
- **Escape các message đưa vào HTML.** Các tham số như tên khách hàng được chèn nguyên vẹn. Điều đó đúng với response JSON, nhưng một email HTML phải escape message như mọi text khác.
- **Để locale lo số và ngày tháng, còn tiền tệ và múi giờ thì không.** Xem [Định dạng giá và ngày tháng](/application/i18n#format-prices-and-dates).

#### Tham khảo <a id="reference"></a>

##### Tùy chọn module <a id="module-options"></a>

`I18nModule.forRoot()` nhận các tùy chọn này. `forRootAsync()` nhận cùng các giá trị từ factory của nó (`useFactory` với `inject`, hoặc một class `useClass` hay `useExisting` implement `I18nOptionsFactory`), trong khi `imports`, `isGlobal` và các class loader, resolver hay formatter vẫn nằm ở cấp cao nhất. Xem [Tùy chọn lấy từ cấu hình](/application/i18n#options-from-configuration). Các tùy chọn đã resolve có thể inject bằng token `I18N_MODULE_OPTIONS`.

| Tùy chọn | Mặc định | Mô tả |
| --- | --- | --- |
| `loader` | bắt buộc | Nguồn của catalog: một instance `I18nLoader` như `JsonI18nLoader`, hoặc một class loader để Nest khởi tạo. Xem [Thêm catalog và đăng ký module](/application/i18n#add-catalogs-and-register-the-module). |
| `resolvers` | `[new AcceptLanguageLocaleResolver()]` | Các locale resolver, được thử theo thứ tự: instance, hoặc class để Nest khởi tạo. |
| `formatter` | cú pháp có sẵn | Một instance `I18nMessageFormatter`, hoặc một class để Nest khởi tạo, chuyển message thành text. Xem [Dùng cú pháp ICU message](/application/i18n#use-icu-message-syntax). |
| `defaultLocale` | `'en'` | Dùng khi không resolver nào tìm được locale được hỗ trợ, và bên ngoài request. |
| `supportedLocales` | các locale đã load | Các locale mà một request có thể nhận, dưới dạng tag BCP 47. |
| `fallbacks` | không có | Một object ánh xạ một locale tới locale mà message của nó được lấy từ đó, như `'de-AT': 'de'`. Các key được tính là locale được hỗ trợ. |
| `missingKey` | `'fallback'` | Giá trị trả về khi thiếu key: `'fallback'`, `'key'`, `'empty'`, `'throw'`, hoặc một hàm nhận key và locale. Xem [Xử lý key bị thiếu và reload catalog](/application/i18n#handle-missing-keys-and-reload-catalogs). |
| `logMissingKeys` | `'once'` | Cảnh báo về key bị thiếu và việc fallback về locale mặc định `'once'` (một lần mỗi key), `'always'` hoặc `'never'`. |
| `responseHeaders` | `true` | Đặt `Content-Language` và `Vary` trên HTTP response. |
| `imports` | không có | Các module có provider được export mà class loader, resolver và formatter inject. |
| `isGlobal` | `true` | Đăng ký module ở cấp global. |

`JsonI18nLoader` nhận `path`, thư mục chứa mỗi locale một thư mục con, và `watch` (mặc định `false`), để reload catalog khi có file thay đổi. `InMemoryI18nLoader` nhận các catalog dưới dạng object có key là locale.

##### Locale resolver <a id="locale-resolvers"></a>

| Resolver | Đọc từ | Tên mặc định |
| --- | --- | --- |
| `QueryLocaleResolver` | một query parameter | `lang` |
| `HeaderLocaleResolver` | một header của request | `x-lang` |
| `AcceptLanguageLocaleResolver` | `Accept-Language`, sắp xếp theo giá trị `q` | không có |
| `CookieLocaleResolver` | một cookie trong header `Cookie` | `lang` |

Một resolver tùy chỉnh kế thừa `LocaleResolver` và implement `resolve()`, method này nhận `headers` và `query` của request, và trả về một ứng viên, một danh sách ứng viên, hoặc không gì cả. Nó liệt kê các header mà nó đọc trong `varyHeaders`. Khi đặt `afterGuards`, nó chạy sau guard, vẫn giữ thứ hạng của mình, và nhận `executionContext`, giống như mọi resolver với microservice, WebSocket gateway và GraphQL subscription. Xem [Dùng ngôn ngữ đã lưu của khách hàng](/application/i18n#use-the-customers-saved-language).

##### API dịch <a id="translation-api"></a>

- `I18nService.t(key, options)`: dịch theo locale hiện tại. `options` nhận `args`, các giá trị cho placeholder (một `count` dạng số sẽ chọn dạng số nhiều), và `locale`, một locale tường minh. Xem [Dịch xác nhận đơn hàng](/application/i18n#translate-order-confirmations). `I18nService<OtherTranslations>` kiểm tra key theo một cấu trúc catalog khác.
- `I18nService.translate(key, options)`: giống như trên nhưng với key không được kiểm tra, dành cho key được tạo lúc runtime.
- `I18nService.exists(key, locale)`: cho biết một key có message hay không.
- `I18nService.formatNumber(value, options)` và `formatDate(value, options)`: định dạng `Intl` theo locale hiện tại, với các tùy chọn `Intl` thông thường cộng thêm `locale`. Xem [Định dạng giá và ngày tháng](/application/i18n#format-prices-and-dates).
- `I18nService.matchLocale(candidate)`: ánh xạ một locale, như locale lưu trong hồ sơ, sang một locale được hỗ trợ, hoặc `undefined`.
- `I18nService.defaultLocale` và `supportedLocales`: các locale đã cấu hình, dùng cho bộ chọn ngôn ngữ.
- `I18nContext.locale` và `I18nContext.run(locale, fn)`: đọc locale hiện tại, hoặc đặt một locale làm hiện tại cho code bên ngoài request.
- `I18nContext.setLocale(locale)`: thay đổi locale cho phần còn lại của request và trả về locale đã khớp, hoặc `undefined` với locale không được hỗ trợ (khi đó không thay đổi gì). Nó throw khi ở bên ngoài request, và trong guard của microservice, WebSocket gateway và GraphQL subscription, vì guard chạy trước khi locale được resolve.
- `@CurrentLocale()`: locale hiện tại dưới dạng tham số của handler.
- `t(key, options)`: `I18nService.t()` dành cho code không dùng dependency injection. Bên ngoài request, nó trả về key. Xem [Bản địa hóa exception](/application/i18n#localize-exceptions).
